# Проект

Это фронтенд‑проект с упором на **качественную** вёрстку: семантичный HTML5, аккуратный современный CSS, минимальный, чистый JavaScript без фреймворков по умолчанию.

Основная задача — получать production‑готовый, читаемый и поддерживаемый код, который легко доработать руками разработчика.

---

## ЧТО: стек и структура

- HTML5:
  - Семантические теги: header, main, section, article, aside, footer, nav.
  - Корректная иерархия заголовков (h1–h6), один h1 на страницу.
- CSS:
  - Mobile‑first, responsive design.
  - Организация по BEM: `block`, `block__element`, `block__element--modifier`.
  - Использование CSS‑переменных для цветов, шрифтов и отступов.
  - Сетки только через Flexbox и CSS Grid, без float/layout‑хака.
- JS:
  - Чистый ES6+ без сборщика (если не указано иное).
  - Модули через `type="module"`, минимум глобальных сущностей.
  - JS только для интерактива (табы, модалки, аккордеоны, слайдеры и т.п.), не для версточных костылей.

Структура проекта (по умолчанию):

- `/src/index.html` — точка входа.
- `/src/assets/` — шрифты, изображения, иконки.
- `/src/styles/`:
  - `base.css` — ресет/normalize, базовые токены (цвета, шрифты, отступы).
  - `layout.css` — сетки, контейнеры, глобальные layout‑паттерны.
  - `components/` — отдельный файл под каждый повторяемый компонент.
- `/src/scripts/`:
  - `main.js` — точка входа для фронтовой логики.
  - модуль на каждый независимый компонент с логикой.

Если структура в репозитории отличается, ориентируйся на README и существующие файлы, но сохраняй тот же принцип изоляции компонентов.

## ЗАЧЕМ: цели и критерии качества

Цели:

- Адаптивный, приятный визуально интерфейс без ощущения “нейросеточной” вёрстки.
- Код, который можно сразу положить в прод, максимум с косметическими правками.
- Сильная основа по доступности (a11y) и семантике.

Критерии качества:

- Нет “магических” значений без причины: размеры, отступы, цвета должны быть согласованы.
- Продуманная типографика (иерархия заголовков, читабельный текст, разумная длина строк).
- Никакого дублирования стилей, вынесение повторяющегося в общие компоненты/utility‑классы.
- Вёрстка устойчива к изменению текстов (длинные заголовки не ломают сетку).

## КАК: стиль кода и правила

### HTML

- Всегда валидный HTML5 (doctype, lang, charset, viewport).
- Атрибуты в порядке: `class`, `id`, `data-*`, `aria-*`, остальное.
- Никакого inline‑CSS и inline‑JS.
- Формы:
  - label связан с input через `for`/`id` или обёртку.
  - осмысленные `name`, `type`, placeholder не вместо label.

### CSS

- BEM‑нейминг:
  - Не используем вложенные мод
